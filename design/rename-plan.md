# Renaming the app: what changes (surveyed 2026-11-07, not done)

The name is decided later; until then the app is **MoreCoffee**. When it is decided, everything below is done **in one change**.

**Rule (planner, 2026-11-07): change only what the user sees, and the bundle ID.** The `MoreCoffee` identifiers inside the code stay. A README line says "MoreCoffee is the internal name".

**No App Store Connect app record until the name is decided**: the bundle ID can't change after the first upload.

The permission texts don't contain the name: no change.

## 2. What else a new bundle ID changes

| | Effect |
|---|---|
| **The records on Uryu's phone** | A new bundle ID is a **new app**: an empty database and no photos. The old build stays installed beside it, with the records. V1 has **no import**, so the exported CSV / JSON can't be read back in (`todo.md` T-16). Export before switching, whatever happens. |
| URL scheme | `CFBundleURLTypes` is the bundle ID (`com.uryumyao.MoreCoffee-App`), made by prebuild. Only the debug launch uses it; the app has no deep links. It follows by itself. |
| Signing | A new App ID in the developer account; automatic signing makes its profiles. |
| Entitlements, App Groups, iCloud, Keychain | none used (`MoreCoffee.entitlements` is empty): nothing to move |
| Simulators | the old app stays installed beside the new one; delete it by hand |
| `npm run ios:device` | names the device, not the app: unchanged |
| `ios/` | **regenerated by prebuild** when `expo.name` changes (seen 2026-11-07: `ios/MoreCoffeeApp` became `ios/MoreCoffee`). `ios/` is git-ignored and built from `app.json`, so nothing is lost, but run `pod install` and a full build afterwards. |

## 3. What stays as it is

- The repository (`uryu-myao/MoreCoffee-App`), the local folder, `expo.slug` (`MoreCoffee-App`; Expo's project id, which nobody sees).
- Code identifiers and comments that say MoreCoffee, including tokens and schema.
- **The database file `morecoffee.db`** (`src/data/migrate.ts`): renaming it would orphan the data of every existing install.
- **The JSON export's `app: 'MoreCoffee'` field** (`src/data/export.ts:56`): it marks the format, not the brand. A future import would check it, and older exports must still match.
- The native module names (PhotoStyle, PlaceSearch) and the Xcode project name, whatever prebuild calls it.
- `design/` documents: history stays as written. Only the README gains its one line.

## Replacing the icon and launch screen (Uryu supplies the art)

**Files**

| File | Spec |
|---|---|
| `assets/icon.png` | 1024 × 1024 PNG, sRGB, **opaque (no alpha)**, square corners: iOS rounds them. One size is enough; Xcode makes the others. |
| optional: dark and tinted icons (iOS 18) | the same size; `app.json` `ios.icon` takes `{ light, dark, tinted }`. Not required. |
| the launch image (replaces `assets/splash.png`) | **a logo mark, not a full screen**: a PNG with a transparent background. The current plugin centres it at `imageWidth` (default 200 pt) on `backgroundColor` (`#F4EDEA`, already set), so give it about 3× that, e.g. 600 px wide. Today's 1284 × 2778 full-screen image is the old way. |

**Steps**
1. Put the files in `assets/` (same names, or change the paths in `app.json`; for the launch screen, set `imageWidth` in the `expo-splash-screen` plugin entry).
2. `npx expo prebuild --platform ios`, then `cd ios && pod install`.
3. Build (`npx expo run:ios`, and `npm run ios:device`).
4. Check on device. iOS caches launch screens: if the old one shows, delete the app or restart the phone (**export first**, T-16).

Android's `adaptive-icon.png` and the web favicon aren't used (iOS only).
